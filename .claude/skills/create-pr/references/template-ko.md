# PR 템플릿 (한국어)

한국 팀·한국어 프로젝트용. 모든 섹션은 실제 커밋과 diff를 근거로 채운다. 해당 없는 섹션은 제목까지 통째로 지운다 — 빈 칸, "없음", 플레이스홀더를 남기지 않는다.

## 제목

`<type>: <한국어 요약>` — 50자 안팎, 마침표 없이, "~추가", "~수정", "~개선"처럼 명사형으로 끝낸다.
type: `feat`, `fix`, `refactor`, `chore` (저장소에 정의된 커밋 컨벤션이 있으면 그것을 따른다).
대상 저장소의 최근 PR 제목이 다른 형식(스코프, 티켓 키 등)을 쓰면 그 형식을 따른다.

예:
- `feat: 프롬프트 500자 제한 검증 및 입력 UI 연동`
- `fix: 첫 모델 타임아웃 시 폴백 순서 유지`

## 본문

```markdown
## 개요

<1~3문장. 리뷰어 입장에서 이 PR이 무엇을, 왜 하는지.>

## 변경 사항

- <파일 목록이 아니라 동작 단위로. 관련 수정은 한 줄로 묶는다.>
- <...>

## 배경

<왜 필요한지: 버그, 사용자 문제, 연결된 이슈. 개요에서 이미 설명했다면 생략.>

## 테스트

<실제로 실행한 명령과 결과, 필요하면 수동 확인 절차.>

- `bun run test` — 23개 통과
- <수동 확인: 리뷰어가 따라 할 수 있는 절차>

## 스크린샷

<UI 변경일 때만. 변경 전 / 후. 아니면 섹션 삭제.>

## 리뷰 포인트

<트레이드오프, 범위에서 뺀 후속 작업, 위험한 부분, 호환성 깨짐, 마이그레이션 절차.>

Closes #<이슈 번호>
```

규칙:
- "테스트"에는 이 세션에서 실제로 실행한 명령과 실제 결과만 적는다. 실행하지 않았으면 "로컬에서 실행하지 않음"이라고 그대로 적는다.
- `Closes #N`은 브랜치 이름, 커밋, 사용자 요청에서 이슈 번호를 확인했을 때만 쓴다.
